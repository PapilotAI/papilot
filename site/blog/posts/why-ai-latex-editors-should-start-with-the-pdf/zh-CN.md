在修改学术论文时，研究者的视线几乎总是停留在排版后的 PDF 页面上。你会对着版面通读证明，发现某个记号掩盖了前提假设，或是注意到某张图注没有把曲线的含义交代清楚。然而，一旦打算动手修改——无论是亲自改写还是借助 AI 助手——绝大多数工具都会要求你离开页面，回到 `.tex` 源码文件里去操作。

几十年来，在排版视图与原始 LaTeX 源码之间来回切换，似乎是科学出版天然要付出的代价。如今，代码智能体已经能够跨文件编辑复杂项目，很多人自然会把“AI LaTeX 编辑器”做成在传统代码 IDE 旁挂一个 PDF 预览窗：你向助手发出指令，它返给你一片红绿相间的反斜杠、环境声明和宏调用 diff。

我们在设计 [Papilot](https://github.com/PapilotAI/papilot) 时秉持着一个更直接的理念：既然作者与读者真正关心的都是排版后的成稿，那么 PDF 就应当成为发起修改和审阅结果的主界面，而 LaTeX 则继续在底层保存文稿内容和排版定义。

## 为什么源码 diff 是在让作者替编译器干活

不妨设想一个多文件论文项目里的常见修订场景。你在检查第 7 页的一条引理时，意识到某个估计量的指标集需要把观测样本与留出样本区分开来。要想干净地完成这次修改，你需要更新一处行间公式，调整上下文段落里的行内记号，并核对交叉引用的表注是否仍然一致。

在以源码为中心的工作流里，你得先在多个 `.tex` 文件间找出对应的 `\begin{equation}` 或自定义宏，把上下文复制进提示词，然后等待补丁。当 AI 给出回复时，摆在你面前的是源码 diff。为了判断修改是否准确，你不得不在脑海里充当一次 LaTeX 编译器：心算 `\mathcal`、`\hat`、多层上下标嵌套、间距微调以及宏展开。就算随后编译了项目，你依然要在第 7 页上肉眼搜寻刚才改了哪里，凭记忆与修改前的版面做对比。

源码 diff 有助于核对命令与实现细节，却不能直接展示公式读起来是否清楚、图注与图表的排布是否合适。让研究者透过零碎的 `.tex` 代码块去核实学术论证，等于强迫作者在做学者该做的判断之前，先替编译器做一遍解析工作。

## 让排版后的页面成为工作台

如果把排版后的 PDF 变成直接操控的工作面，体验会发生怎样的变化？Papilot 不再把编译产物视为流水线末端被动的预览图，而是让排版页面成为每一次修订循环的起点与终点。

![展示四阶段修订循环的示意图：作者在渲染后的 PDF 上批注，接入的 AI 智能体编辑底层 .tex 文件，Papilot 编译项目，随后作者在 PDF 上审阅排版后的修改前后对比并进入下一轮循环。](/assets/blog/pdf-first-workflow.zh-CN.svg "在 Papilot 中，作者始终停留在排版页面上提出需求并审阅修改，底层 .tex 源码的定位、编辑与编译则交给智能体和编译器完成。")

整个工作流构成一个直观的闭环：

- **在页面上直接批注：** 直接在 PDF 上高亮句子，或框选公式、表格与插图，写下简短的批注说明修改意图。
- **交由智能体修改源码：** 已接入的 AI 智能体会在本地项目中定位相关的 `.tex` 文件，并对底层 LaTeX 标记进行编辑。
- **后台自动编译：** Papilot 自动编译修改后的项目，生成最新的排版结果。
- **基于版面进行 PDF 审阅：** 无需阅读枯燥的源码 diff，你可以直接在页面上查看排版后的修改前后对比，决定接受、拒绝，或追加批注要求继续调整。

需要强调的是，这并不意味着抛弃 LaTeX，也不是对某个没有源码的任意 PDF 做逆向工程。Papilot 运行在你本机真实的 LaTeX 项目目录之上。磁盘上保存的依然是标准的 `.tex`、`.bib` 和样式文件，让你在保留科学排版全部优势的同时，不必为了日常推敲和改稿而深陷繁琐的源码标记。

## 更直观的审阅视图，不能替代学者的专业把关

看得清楚，不代表改得正确。AI 智能体可以把一处记号变更同步到三个章节，或是把一段冗长的证明草稿改写得紧凑流畅，但在这个过程中，它也可能悄然弱化某个定理条件、漏掉边界情形，或是曲解图表所展示的实验结论。

降低 PDF 审阅的阻力，是为了让作者的学术把关更专注，而不是放松警惕。当你不再需要分心去核对花括号是否配对、表格列对齐符是否错位时，就能把全部精力放回真正关键的问题上：定理推导是否依然严密？记号约定是否毫无歧义？正文表述是否经得起同行推敲？AI 给出的每一处建议都必须经过严格的学术核查，作者始终对论文中的论点、公式与图表负全部责任。

## 本地文件、Git 历史与自选智能体

一篇学术论文的打磨往往历时数月，涉及习惯各异的合作者，也依赖于个人或团队既有的工具链。理想的写作环境应当顺应这种现实，而不是把文稿锁进封闭的云端数据库。

由于 Papilot 直接读写本地纯文本文件，你的项目能够自然融入标准的 Git 工作流与多人协作方式。在界面中审阅排版修改与管理版本历史是两个独立的环节：接受一条建议会记录审阅决定；把审阅后的改动应用到稿件、提交（commit）或推送到远端仓库，仍是由你明确发起的操作。

同样的原则也适用于底层模型与运行环境。在 macOS、Linux 或 Windows 上使用桌面端时，你只需准备好本地 TeX 发行版（如 TeX Live 或 MacTeX）、Git，以及你平时惯用的 AI 智能体——无论是 Claude、Codex、Cursor、Copilot，还是 DeepSeek、Kimi、Qwen 等支持的 CLI 登录或 API 密钥。Papilot 本身采用 MIT 开源协议免费发布，模型用量使用你所选服务商的账户。
